    5. Enrutamiento

    Una aplicación tiene varias pantallas. En la web, cada pantalla tiene una dirección (/ex17/doctors/2): se puede referenciar, abrir mediante un enlace, recargar o proteger con guardias. [Angular] administra estas direcciones mediante su enrutador (el paquete [@angular/router]), que hemos venido usando desde el primer ejemplo: la página de inicio de la aplicación de ejemplos asocia la dirección /ex01 con la página del ejemplo 01, /ex02 con la página del ejemplo 02, y así sucesivamente. [Ionic] no reemplaza este enrutador: se apoya en él y agrega las funcionalidades que se esperan de una aplicación móvil. Su componente [<ion-router-outlet>] organiza las páginas en una pila: una página nueva se apila sobre la anterior (con la animación de Android), el botón Atrás del teléfono la quita de la pila y la página anterior, que permanece en memoria, reaparece exactamente como se dejó. Combina el [Navigator] de [Flutter] y el paquete [go_router].

    5.1. Ejemplo 17: el enrutador

    El ejemplo 17 tiene seis páginas: una página de inicio, una lista de médicos, el perfil de un médico, una página de búsqueda, una página “About” cargada bajo demanda y una página para direcciones desconocidas. Las cinco primeras se agrupan en un “shell”, con una barra de pestañas en la parte inferior de la pantalla (cuatro pestañas: la página de detalles de un médico pertenece a la pestaña Doctors).

    // =========================================================================
// src/app/ex17-router/routes.ts - las RUTAS del ejemplo 17
// -------------------------------------------------------------------------
// Una aplicación tiene varias pantallas ("páginas"). El ENRUTADOR de Angular
// asocia una DIRECCIÓN (una ruta, como en la web: /ex17/doctors/2) con
// una página. Ionic se apoya en él: su <ion-router-outlet> lo convierte en una
// PILA de páginas (apilamos, desapilamos, el botón Atrás de Android desapila).
// Estas rutas son las HIJAS de la ruta /ex17 de app.routes.ts
// (loadChildren): sus rutas son relativas a /ex17.
//   'doctors/:id'    :id es un parámetro (/ex17/doctors/2 -> id = "2");
//   children         rutas mostradas DENTRO del "shell" (la barra
//                    superior, la barra de pestañas inferior);
//   redirectTo       una redirección: la dirección antigua lleva a la nueva;
//   '**'             el "comodín": cualquier dirección que ninguna ruta reconoce;
//   title            el título del documento (pestaña del navegador);
//   loadComponent    carga DIFERIDA: el código de la página solo se
//                    descarga en su primera visita.
// =========================================================================

import { ResolveFn, Routes } from '@angular/router';
import { Shell } from './shell';
import { doctors } from './data';
import { Home } from './pages/home.page';
import { DoctorDetail } from './pages/doctor-detail.page';
import { DoctorList } from './pages/doctor-list.page';
import { NotFoundPage } from './pages/not-found.page';
import { Search } from './pages/search.page';

// el título de la página de un médico, calculado a partir del parámetro :id de la dirección
const doctorTitle: ResolveFn<string> = (route) => {
  const doctor = doctors.find((m) => m.id === Number(route.paramMap.get('id')));
  return doctor ? `${doctor.firstName} ${doctor.lastName}` : 'Unknown doctor';
};

export const routes: Routes = [
  {
    // el shell (Shell) contiene la barra de pestañas; sus rutas hijas
    // se muestran DENTRO del shell, encima de la barra
    path: '',
    component: Shell,
    children: [
      // solo /ex17: vamos a la pestaña de inicio
      { path: '', redirectTo: 'home', pathMatch: 'full' },
      { path: 'home', title: 'Home', component: Home },
      { path: 'doctors', title: 'Doctors', component: DoctorList },
      // una página con un PARÁMETRO: /ex17/doctors/2; comienza con
      // 'doctors': pertenece a la pestaña Doctors, de la cual
      // apila una página sobre la lista
      { path: 'doctors/:id', title: doctorTitle, component: DoctorDetail },
      // /ex17/search?q=pediatrician: el parámetro q es un parámetro de CONSULTA (query)
      { path: 'search', title: 'Search', component: Search },
      // carga diferida: import() es una importación DINÁMICA
      // (una Promise); el código de la página se coloca en un archivo aparte
      {
        path: 'about',
        title: 'About',
        loadComponent: () => import('./pages/about.page').then((m) => m.About),
      },
      // una redirección: la ruta no tiene página, envía a otra dirección
      { path: 'physicians', redirectTo: 'doctors' },
    ],
  },
  // cualquier otra dirección bajo /ex17: la página de no encontrado, FUERA del shell
  { path: '**', title: 'Page not found', component: NotFoundPage },
];

    Una ruta asocia una ruta de acceso con una página. Las rutas del ejemplo 17 se almacenan en su carpeta, y la ruta /ex17 de la aplicación las carga mediante [loadChildren] (se explica más adelante): son rutas hijas de /ex17, y sus rutas de acceso son relativas a /ex17 ([home] se refiere a la dirección /ex17/home).

    • Líneas 30–33: una función de tipo [ResolveFn<string>], que calcula el título de la página de un médico a partir del parámetro [:id] de la URL ([route.paramMap.get('id')]). La propiedad [title] de una ruta es el título del documento (la pestaña del navegador en la web): una cadena o una función de este tipo. Es el equivalente del widget [Title] de [Flutter];
    • Líneas 36–41: el shell del ejemplo. La ruta no tiene ruta de acceso propia ([path: '']); muestra el componente [Shell] (la barra superior y la barra de pestañas), y sus rutas hijas ([children]) se muestran EN el shell. Equivale a [ShellRoute] de [go_router];
    • línea 43: la dirección /ex17 sola se redirige a /ex17/home. [pathMatch: 'full']: la ruta se aplica solo si la dirección restante está vacía (de lo contrario, la ruta de acceso vacía, que es el comienzo de toda dirección, se aplicaría siempre);
    • líneas 44–45: una ruta estándar: su ruta de acceso, su título y su componente de página;
    • línea 49: una ruta con un parámetro: [doctors/:id], donde [:id] es un parámetro ([/ex17/doctors/2]: [id] equivale a ["2"], que siempre es una cadena). Con [go_router], esta ruta estaba anidada dentro de la de la lista; aquí es adyacente a ella. Su ruta de acceso comienza con [doctors]: para [Ionic], pertenece a la pestaña Doctors, y su página se apila sobre la lista, en la pila de esa pestaña;
    • línea 51: la búsqueda. Sus parámetros de consulta (después de [?]: [/ex17/search?q=pediatrician]) no aparecen en la ruta de acceso: cualquier ruta puede aceptarlos;
    • Líneas 54–58: carga diferida. [loadComponent] es una función que devuelve una [Promise]: [import('./pages/about.page')] es una importación dinámica de [JavaScript], que carga el archivo al ejecutarse, y [then] extrae de él el componente. La compilación ([ng build]) coloca entonces el código de la página en un archivo [JavaScript] aparte, que se descarga en la primera visita a la página. Es el equivalente de la importación de [Dart] con [deferred as];
    • línea 60: una redirección: la ruta no tiene página; redirige a otra dirección. [redirectTo] también puede ser una función que calcula la dirección;
    • línea 64: la ruta comodín [**] coincide con cualquier dirección que ninguna ruta anterior haya reconocido (el enrutador prueba las rutas en orden). Se coloca fuera del shell: la página “página no encontrada” tiene su propia barra de encabezado. Es el equivalente de [errorBuilder] de [go_router].

    // =========================================================================
// src/app/ex17-router/shell.ts - el "shell" del ejemplo 17
// -------------------------------------------------------------------------
// La barra superior, la barra de pestañas inferior y, entre las dos, la página
// de la ruta actual. Es el componente <ion-tabs> de Ionic:
//   - <ion-tab-bar slot="bottom">: la barra de pestañas, en la parte inferior;
//   - <ion-tab-button tab="doctors">: una pestaña; al tocarla se va a
//     la dirección /ex17/doctors. La pestaña activa es aquella cuyo nombre es el
//     primer segmento de la dirección (después de /ex17): /ex17/doctors/2 -> Doctors;
//   - cada pestaña tiene su PROPIA pila de páginas: podemos entrar en el
//     detalle de un médico, cambiar a la pestaña Search, volver a la
//     pestaña Doctors... y encontrar de nuevo el detalle.
// =========================================================================

import { Component, computed, inject } from '@angular/core';
import { Router } from '@angular/router';
import {
  IonBackButton, IonButtons, IonHeader, IonIcon, IonLabel, IonTabBar, IonTabButton, IonTabs, IonTitle, IonToolbar,
} from '@ionic/angular';
import { addIcons } from 'ionicons';
import { home, informationCircle, people, search } from 'ionicons/icons';
import { DeferredLoading } from './pages/deferred-loading';

// las pestañas: el nombre de la pestaña (= la ruta, después de /ex17), la etiqueta, el ícono
const tabs = [
  { tab: 'home', label: 'Home', icon: 'home' },
  { tab: 'doctors', label: 'Doctors', icon: 'people' },
  { tab: 'search', label: 'Search', icon: 'search' },
  { tab: 'about', label: 'About', icon: 'information-circle' },
];

@Component({
  selector: 'app-ex17-shell',
  imports: [
    IonTabs, IonTabBar, IonTabButton, IonIcon, IonLabel, IonHeader, IonToolbar, IonButtons, IonBackButton, IonTitle,
    DeferredLoading,
  ],
  templateUrl: './shell.html',
  styles: `
    .address {
      background: var(--ion-color-light);
      color: var(--ion-color-light-contrast);
      padding: 8px;
      font-family: monospace;
      font-size: 12px;
    }
  `,
})
export class Shell {
  readonly tabs = tabs;
  private readonly router = inject(Router);

  // la dirección actual. lastSuccessfulNavigation es un SIGNAL del router:
  // la última navegación exitosa; finalUrl: su dirección, después de las
  // redirecciones. decodeURIComponent: %20 vuelve a ser un espacio
  readonly address = computed(() => {
    const navigation = this.router.lastSuccessfulNavigation();
    return navigation?.finalUrl ? decodeURIComponent(this.router.serializeUrl(navigation.finalUrl)) : '';
  });

  constructor() {
    // los íconos usados por la plantilla
    addIcons({ home, people, search, informationCircle });
  }
}

<ion-tabs>

  <ion-header slot="top">

      </ion-buttons>
      <ion-title>Example 17 - the router</ion-title>
    </ion-toolbar>

  <ion-tab-bar slot="bottom">
    @for (tab of tabs; track tab.tab) {
      <ion-tab-button [tab]="tab.tab">
        <ion-icon [name]="tab.icon" />
        <ion-label>{{ tab.label }}</ion-label>
      </ion-tab-button>
    }
  </ion-tab-bar>
</ion-tabs>

    El shell es el componente [<ion-tabs>] de [Ionic]: una barra de pestañas y, encima de ella, la página de la pestaña seleccionada.

    • líneas 25–30 (shell.ts): las pestañas: un nombre (que también es la ruta de acceso después de /ex17), una etiqueta y un ícono;
    • líneas 56–59 (shell.ts): la dirección actual, un signal calculado ([computed]). El enrutador expone signals: [lastSuccessfulNavigation()], la última navegación exitosa, y [currentNavigation()], la navegación en curso (se explica más adelante). [finalUrl] es la dirección de destino, después de las redirecciones; [serializeUrl] la convierte en una cadena; [decodeURIComponent] decodifica los caracteres codificados ([%20] vuelve a ser un espacio). Como el signal se vuelve a leer con cada navegación, la dirección mostrada lo sigue;
    • línea 63 (shell.ts): los íconos que usa la plantilla;
    • líneas 7–18 (shell.html): la barra superior. [<ion-tabs>] coloca los elementos marcados con [slot="top"] encima de las páginas de las pestañas, y los demás debajo. El botón Atrás de esta barra cierra todo el shell: lo devuelve al menú de ejemplos;
    • línea 15 (shell.html): la dirección actual;
    • línea 17 (shell.html): una barra de progreso, que se muestra durante la navegación (véase más abajo);
    • líneas 20–21 (shell.html): [<ion-tabs>] coloca por sí mismo, entre las dos barras, un [<ion-router-outlet>]: la página de la ruta hija actual. Nosotros no escribimos esto;
    • líneas 24–31 (shell.html): la barra de pestañas inferior ([<ion-tab-bar slot="bottom">]), típica de una aplicación móvil, es el equivalente de [NavigationBar] de [Flutter]. Cada [<ion-tab-button [tab]="...">] es una pestaña; al tocarla se llega a la dirección /ex17/<tab name>.

    Dos diferencias con [go_router]:

    • el código no calcula la pestaña activa: [<ion-tabs>] la deduce de la URL (la pestaña cuyo nombre es el primer segmento de la URL, después de /ex17: [/ex17/doctors/2] corresponde a la pestaña [doctors]);
    • Cada pestaña tiene su propia pila de páginas. Si ve los detalles de un médico, cambia a la pestaña Search y luego regresa a la pestaña Doctors, verá de nuevo los detalles del médico, y el botón Atrás lo lleva de vuelta a la lista. Este es el comportamiento estándar de las aplicaciones móviles (como las de [Android] y [iOS]).

    // =========================================================================
// src/app/ex17-router/pages/doctor-detail.page.ts - una página con un parámetro
// -------------------------------------------------------------------------
// El enrutador entrega el parámetro :id de la dirección al INPUT id de la página
// (input), una CADENA ("2"): eso es withComponentInputBinding() (main.ts).
// Si pasamos de /ex17/doctors/1 a /ex17/doctors/2, Angular conserva la
// misma página y solo cambia el valor del input: el médico mostrado,
// calculado (computed) a partir de él, lo sigue.
// Navegación por CÓDIGO: NavController, el servicio de navegación de Ionic.
// =========================================================================

import { Component, computed, inject, input } from '@angular/core';
import { IonButton, IonContent, IonRouterOutlet, IonText, NavController } from '@ionic/angular';
import { doctors } from '../data';

@Component({
  selector: 'app-ex17-doctor-detail',
  imports: [IonContent, IonButton, IonText],
  templateUrl: './doctor-detail.page.html',
})
export class DoctorDetail {
  // el parámetro :id de la dirección
  readonly id = input.required<string>();

  // Number("abc") es NaN: no se encontrará ningún médico (undefined)
  readonly doctor = computed(() => doctors.find((m) => m.id === Number(this.id())));
  // el número del siguiente médico: 1 -> 2 -> 3 -> 1
  readonly next = computed(() => ((this.doctor()?.id ?? 0) % doctors.length) + 1);

  private readonly navCtrl = inject(NavController);
  // la pila de páginas de la pestaña (el <ion-router-outlet> que muestra esta página)
  private readonly outlet = inject(IonRouterOutlet);

  back(): void {
    // canGoBack: ¿hay una página debajo? (no si llegamos
    // directamente a esta dirección, en la web)
    if (this.outlet.canGoBack()) {
      this.outlet.pop();
    } else {
      this.navCtrl.navigateBack('/ex17/doctors');
    }
  }

  nextDoctor(): void {
    // replaceUrl: la dirección REEMPLAZA a la dirección actual en el historial
    // (sin apilar: el botón Atrás lleva de vuelta a la lista)
    this.navCtrl.navigateForward(['/ex17/doctors', this.next()], { replaceUrl: true });
  }
}

import { Component, computed, inject, input } from '@angular/core';
import { Router } from '@angular/router';
import { IonContent, IonItem, IonLabel, IonList, IonSearchbar } from '@ionic/angular';
import { doctors } from '../data';

@Component({
  selector: 'app-ex17-search',
  imports: [IonContent, IonSearchbar, IonList, IonItem, IonLabel],
  templateUrl: './search.page.html',
})
export class Search {
  // el parámetro ?q=... de la dirección
  readonly q = input<string>();

  // los resultados: se recalculan cuando cambia la dirección (y por tanto q)
  readonly results = computed(() => {
    const text = (this.q() ?? '').toLowerCase();
    return doctors.filter((m) => `${m.firstName} ${m.lastName} ${m.specialty}`.toLowerCase().includes(text));

    // necesario (espacio -> %20)
    this.router.navigate(['/ex17/search'], { queryParams: { q: input.trim() } });
  }
}

    En un navegador ([ng serve]), la dirección también aparece en la barra de direcciones, los botones Atrás y Adelante funcionan, y se puede escribir una dirección manualmente: /ex17/doctors/3, /ex17/search?q=pediatrician, /ex17/physicians....

    En comparación con [go_router], el enrutador de [Angular] es más declarativo: las rutas son una simple lista de objetos, los parámetros se pasan a los campos de entrada de la página y la carga diferida es simplemente una propiedad de la ruta. [Ionic] agrega funcionalidades propias de los dispositivos móviles: la pila de páginas ([<ion-router-outlet>]), las pestañas con pilas separadas ([<ion-tabs>]), la dirección de la navegación y las animaciones de navegación ([NavController]). Encontraremos exactamente los mismos conceptos en el cliente [Angular] de [RdvMedecins] (las rutas, [routerLink], [router.navigate]): solo los componentes de [Ionic] son específicos de los dispositivos móviles.

// src/app/ex18-guards/session.ts - una sesión SIMULADA (sin servidor)
// -------------------------------------------------------------------------
// El usuario que ha iniciado sesión debe ser conocido por las PÁGINAS (la barra superior,
// la agenda) y por los GUARDS del enrutador (funciones, que no son
// componentes). Lo almacenamos en un SERVICIO, un único objeto que todos
// obtienen con inject(Session) (vea el ejemplo 14):
//   - un signal privado, el estado;
//   - una vista de solo lectura de este signal;
//   - métodos para modificarlo.
// Quienes leen el signal (las plantillas) son notificados cuando cambia.
// (El ejemplo 23 hará lo mismo con un servidor real.)
// =========================================================================

import { Injectable, signal } from '@angular/core';

export type Role = 'ADMIN' | 'DOCTOR' | 'USER';

export interface User {
  login: string;
  role: Role;
}

// tres cuentas "codificadas de forma fija" (contraseña = login)
const accounts: Record<string, Role> = { admin: 'ADMIN', pelissier: 'DOCTOR', martin: 'USER' };

// providedIn: 'root': UNA sola instancia, para toda la aplicación
@Injectable({ providedIn: 'root' })
export class Session {
  // el estado: null, nadie ha iniciado sesión
  private readonly _user = signal<User | null>(null);
  // asReadonly: podemos leer el signal, no modificarlo
  readonly user = this._user.asReadonly();

  logIn(login: string, password: string): boolean {
    const role = accounts[login];
    if (role === undefined || password !== login) {
      return false;
    }
    this._user.set({ login, role });
    return true;
  }

  logOut(): void {
    this._user.set(null);
  }
}

    Las páginas (la barra superior, la agenda) y los guardias del enrutador, que no son componentes, deben reconocer al usuario que inició sesión. Este se almacena en un servicio (véase el ejemplo 14), un objeto único que todos obtienen mediante [inject(Session)]:

    • líneas 17–22: los roles (un tipo “unión” formado por tres cadenas) y el usuario;
    • línea 25: tres cuentas “escritas en el código” (contraseña = nombre de usuario): un objeto que asocia un nombre de usuario con un rol ([Record<string, Role>]);
    • línea 28: [providedIn: 'root']: una única instancia del servicio para toda la aplicación;
    • líneas 31–33: el estado, un signal privado ([null]: nadie ha iniciado sesión) y su vista de solo lectura ([asReadonly()]): los demás pueden leerlo, pero solo los métodos del servicio pueden modificarlo;
    • líneas 35–42: la conexión, simulada. Modifica el signal: todo lo que lo lee (plantillas, signals calculados) lo sigue. Este es el [notifyListeners()] del [ChangeNotifier] de [Flutter], sin tener que escribirlo. (El ejemplo 23 hará lo mismo con un servidor real.)

    // =========================================================================
// src/app/ex18-guards/routes.ts - rutas PROTEGIDAS por guardias
// -------------------------------------------------------------------------
// canActivate: la lista de las GUARDIAS de una ruta, funciones (de tipo
// CanActivateFn) que el enrutador llama ANTES de ir allí. Una guardia recibe
// la ruta solicitada y el estado de la navegación (state.url: la dirección
// solicitada), y devuelve:
//   - true: la navegación continúa;
//   - false: se cancela;
//   - un UrlTree (una dirección construida por el enrutador): la navegación
//     se reemplaza por una navegación hacia esta dirección.
// Una guardia puede usar inject(): se la llama en un "contexto
// de inyección".
//
// Es el equivalente del lado del cliente de las guardias de NestJS (JwtAuthGuard,
// RolesGuard), con una diferencia FUNDAMENTAL: una guardia del cliente es
// solo una comodidad. La aplicación está en manos del usuario, que
// puede modificarla a voluntad. La protección real de los datos sigue siendo
// la del SERVIDOR (véase el capítulo sobre la caja negra).
// =========================================================================

import { inject } from '@angular/core';
import { CanActivateFn, Router, Routes } from '@angular/router';
import { Shell } from './shell';
import { Home } from './pages/home.page';
import { Schedule } from './pages/schedule.page';
import { Login } from './pages/login.page';
import { Role, Session } from './session';

// la guardia "login requerido": sin sesión iniciada -> a la página de inicio de sesión,
// recordando adónde se quería ir (parámetro returnUrl)
export const loginRequired: CanActivateFn = (route, state) => {
  if (inject(Session).user() === null) {
    return inject(Router).createUrlTree(['/ex18/login'], { queryParams: { returnUrl: state.url } });
  }
  return true;
};

// la guardia "rol requerido": una función que CONSTRUYE una guardia
export function roleRequired(...roles: Role[]): CanActivateFn {
  return (route, state) => {
    const u = inject(Session).user();
    if (u === null || !roles.includes(u.role)) {
      // con sesión iniciada, pero sin el rol adecuado: de vuelta al inicio, con un motivo
      return inject(Router).createUrlTree(['/ex18'], { queryParams: { denied: state.url } });
    }
    return true;
  };
}

export const routes: Routes = [
  {
    path: '',
    component: Shell,
    children: [
      { path: '', pathMatch: 'full', component: Home },
      { path: 'login', component: Login },
      { path: 'schedule', canActivate: [loginRequired], component: Schedule },
      {
        path: 'administration',
        // las guardias, en orden: gana la primera que no devuelve true
        canActivate: [loginRequired, roleRequired('ADMIN')],
        // el código de la página solo se carga una vez superadas las guardias
        loadComponent: () => import('./pages/administration.page').then((m) => m.Administration),
      },
      // cualquier otra dirección (ninguna ruta coincide): de vuelta al inicio
      { path: '**', redirectTo: '' },
    ],
  },
];

    Un guardia de activación es una función de tipo [CanActivateFn], colocada en la lista [canActivate] de una ruta. El enrutador la llama antes de acceder a esa ruta; recibe la ruta solicitada y el estado de la navegación ([state.url]: la dirección solicitada), y devuelve:

    • [true]: la navegación continúa;
    • [false]: la navegación se cancela;
    • un [UrlTree], una dirección generada por el enrutador ([router.createUrlTree]): la navegación se reemplaza por una navegación a esa dirección.

    Un guardia también puede devolver una [Promise] o un [Observable] con uno de estos valores (para consultar un servidor, por ejemplo). El código:

    • líneas 32–37: el guardia de “inicio de sesión requerido”: ¿no ha iniciado sesión? Redirige a la página de inicio de sesión, conservando el destino previsto (parámetro de consulta [returnUrl]). El guardia usa [inject()]: el enrutador lo llama en un “contexto de inyección”;
    • líneas 40–49: el guardia de “rol requerido” es CONSTRUIDO por una función, que recibe los roles permitidos ([...roles]: tantos parámetros como se desee, agrupados en un arreglo) y devuelve el guardia. ¿Inició sesión, pero sin el rol correcto? Se redirige a la página de inicio, con un motivo (parámetro [denied]);
    • líneas 52–55: el shell y sus rutas hijas, como en el Ejemplo 17;
    • línea 58: la página de la agenda requiere que el usuario haya iniciado sesión;
    • líneas 59–65: la administración requiere que el usuario haya iniciado sesión Y tenga el rol ADMIN. Los guardias de la lista se invocan en orden; el primero que no devuelve [true] gana (en este caso, era la cadena de [??] a [go_router]). El código de la página se carga ([loadComponent]) solo después de que se hayan superado los guardias;
    • línea 67: cualquier otra dirección bajo /ex18 redirige a la página de inicio.

    Este es el equivalente en el cliente de las salvaguardas del servidor [NestJS] ([JwtAuthGuard], [RolesGuard]), con una diferencia FUNDAMENTAL: una salvaguarda del cliente es solo una comodidad (para evitar mostrar una pantalla innecesaria). La aplicación está en manos del usuario, quien puede modificarla a voluntad; la verdadera protección de los datos sigue estando en el servidor, que vuelve a verificar todo con cada solicitud (véase el capítulo sobre la caja negra).

    Una diferencia con [go_router]: su opción [refreshListenable] reevaluaba los guardias de la página actual con cada cambio de sesión (se le redirigía a la página de inicio de sesión si cerraba sesión desde el calendario). El enrutador de [Angular] solo invoca los guardias al navegar. Por eso, después de cerrar sesión (como se describe más adelante) se navega a la página de inicio.

    // =========================================================================
// src/app/ex18-guards/pages/login.page.ts - la página de inicio de sesión
// -------------------------------------------------------------------------
// Tras iniciar sesión, se envía al usuario de vuelta a la página que quería
// abrir (parámetro ?returnUrl=... colocado allí por la guardia), o al inicio.
// =========================================================================

import { Component, inject, input, signal } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { Router } from '@angular/router';
import { IonButton, IonCard, IonCardContent, IonInput, IonText } from '@ionic/angular';
import { Session } from '../session';

@Component({
  selector: 'app-ex18-login',
  imports: [FormsModule, IonCard, IonCardContent, IonInput, IonButton, IonText],
  templateUrl: './login.page.html',
})
export class Login {
  // la dirección solicitada, colocada allí por la guardia loginRequired
  readonly returnUrl = input<string>();

  // los campos del formulario y el error: señales
  readonly login = signal('');
  readonly password = signal('');
  readonly error = signal(false);

  private readonly session = inject(Session);
  private readonly router = inject(Router);

  submit(): void {
    if (!this.session.logIn(this.login().trim(), this.password())) {
      this.error.set(true);
      return;
    }
    // solo se acepta una ruta INTERNA: empieza con /, pero no con //
    // (//site.com/... designa OTRO sitio): ninguna redirección hacia otro sitio
    const r = this.returnUrl();
    const internal = r !== undefined && r.startsWith('/') && !r.startsWith('//');
    this.router.navigateByUrl(internal ? r : '/ex18');
  }
}
