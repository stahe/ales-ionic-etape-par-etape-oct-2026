    2. Configuración del entorno de desarrollo

    2.1. Instalación de las herramientas

    1. Node.js: descargue e instale la versión 24 (LTS) desde nodejs.org. [Angular CLI] 22 requiere [Node.js] 22.22.3 (o una versión 22 más reciente), 24.15 o superior, o 26 y posteriores: una versión anterior no podrá ejecutar el comando [ng]. El instalador también instala [npm], el administrador de paquetes de [Node.js]. Verifique la instalación en una terminal:
    1
2
    node --version
npm --version

    1. Visual Studio Code ([VS Code]): se puede descargar gratuitamente en code.visualstudio.com. Instale las extensiones [Angular Language Service] (autocompletado y validación en las plantillas [HTML]) e [Ionic] (comandos de [Ionic] y [Capacitor] en el editor). La compatibilidad con [TypeScript] ya está integrada en [VS Code].

    2. Chrome: el navegador utilizado para desarrollar la aplicación (google.com/chrome). Sus herramientas para desarrolladores (F12) muestran la aplicación con el tamaño de un teléfono y también permiten depurar la aplicación instalada en el teléfono (vea los apéndices).

    3. MySQL 8 (o MariaDB): necesario únicamente para el servidor JSON. Instálelo, por ejemplo, mediante Laragon (en [Windows]), XAMPP, o directamente mediante MySQL Community Server. Una herramienta gráfica de administración ([HeidiSQL], [phpMyAdmin], [MySQL Workbench], [DBeaver]...) facilita el resto del proceso. Este curso utiliza [Laragon].

    2.2. Instalación del cliente Ionic

    Con [Flutter], había que instalar un SDK: el framework, el lenguaje [Dart] y sus herramientas, comunes a todos los proyectos. Con [Ionic], no hay ningún SDK que instalar: [Angular], [Ionic], [Capacitor], el compilador de [TypeScript] y sus herramientas de línea de comandos ([ng], [cap]) son simples paquetes [npm], declarados en el archivo [package.json] de cada proyecto e instalados en su carpeta [node_modules/]. Así, cada proyecto tiene sus propias versiones, y dos proyectos pueden usar versiones distintas de [Angular] sin interferir entre sí.

    Instalar el cliente [Ionic] de un proyecto significa, por lo tanto, instalar sus paquetes. En [VS Code], abra la carpeta del proyecto (menú Archivo / Abrir carpeta, por ejemplo, la carpeta [examples_ionic]), luego abra una consola (menú Terminal / Nuevo terminal) y escriba:

    1
    npm install

    Este comando descarga los paquetes descritos en [package.json] (junto con sus dependencias: varios cientos de paquetes, con un total de unos cientos de megabytes) en las versiones exactas indicadas en [package-lock.json]. Solo es necesario volver a ejecutarlo si agrega un paquete o cambia una versión.

    Las herramientas del proyecto se inician entonces mediante [npx], que ejecuta el comando de un paquete instalado dentro del proyecto (sin [npx], la consola buscaría un comando instalado en todo el sistema). El comando [npx ng version] verifica la instalación de [Angular]:

    1
    npx ng version

    El resultado es similar a este (aquí en [Linux]; en [Windows], la línea [Operating System] muestra [win32 x64]):

    Solo queda ejecutar la aplicación en la misma consola:

    1
    npm start

    luego abra la dirección [http://localhost:8100] en [Chrome]: allí verá el menú de los 25 ejemplos (vea el ejemplo 01).     La herramienta [@ionic/cli] (opcional). El equipo de [Ionic] también publica una herramienta de línea de comandos, que se instala en todo el sistema:

    1
2
3
4
    npm install -g @ionic/cli
ionic start
ionic serve
ionic capacitor run android -l --external
    • Línea 1: instala el comando [ionic];
    • línea 2: crea un nuevo proyecto [Ionic] + [Angular] + [Capacitor] a partir de una plantilla ([blank]: una página en blanco, [tabs]: pestañas, [sidemenu]: un menú lateral), haciendo algunas preguntas;
    • línea 3: inicia el servidor de desarrollo (que a su vez llama a [ng serve]);
    • línea 4: compila la aplicación, la instala en un dispositivo ([Android]), y la recarga cada vez que se modifica el código ([-l], “live reload”); [--external] hace que el servidor de desarrollo escuche en la dirección de la computadora en la red local, a la que el teléfono puede acceder.

    Esto es solo una comodidad: [ionic] simplemente encadena los comandos [ng] y [cap], y requiere un archivo [ionic.config.json] en el proyecto (que crea [ionic start], o [ionic init] para un proyecto existente). Los proyectos de este curso no lo tienen: se crearon con [ng new] (vea el ejemplo 01) y usamos directamente [ng] y [cap] , que forman parte del proyecto. Es la forma más directa de ver lo que sucede, y no depende de ninguna herramienta instalada en la computadora.

    Ahora describiremos cómo instalar las herramientas para desarrollar en [Android].

    2.3. Android Studio y las herramientas de línea de comandos de Android

    El dispositivo de destino de este curso es un teléfono [Android]. Para construir la aplicación [Android] e instalarla en este teléfono, [Capacitor] requiere el SDK de [Android], y un JDK (el compilador de [Java], utilizado por la herramienta de construcción [Gradle]), que se instalan junto con [Android Studio], el entorno de desarrollo de [Google]. [Android Studio] no se usa para escribir código (el editor sigue siendo [VS Code]): aquí se usa para instalar y actualizar el SDK de [Android], para crear emuladores y, ocasionalmente, para abrir el proyecto [Android] creado por [Capacitor] ([npx cap open android]).

    1. [Android Studio]: descárguelo gratuitamente desde developer.android.com/studio, y luego instálelo. Cuando lo inicie por primera vez, el asistente ofrecerá una instalación estándar: acéptela y descargará el SDK de [Android].

    2. Abra [SDK Manager] desde [Android Studio] (el menú [Tools / SDK Manager] cuando hay un proyecto abierto, o [More Actions / SDK Manager] desde la pantalla de inicio): esta herramienta instala y actualiza los componentes del SDK de [Android].

    3. Pestaña [SDK Platforms]: verifique que esté instalada una plataforma [Android] reciente. [Capacitor] 8 compila las aplicaciones para la API 36 ([Android] 16);

    4. Pestaña [SDK Tools]: marque [Android SDK Build-Tools], [Android SDK Platform-Tools] (que contiene [adb], la herramienta que conecta la computadora con el dispositivo), [Android Emulator] (si desea probar en un emulador) y [Android SDK Command-line Tools (latest)] (que incluye la herramienta [sdkmanager]), y luego haga clic en [Apply].

    5. Acepte las licencias del SDK de [Android]: [Android Studio] las acepta automáticamente cada vez que se instala un componente. Si más adelante la compilación de la aplicación falla por una licencia sin aceptar, acéptelas todas con la herramienta [sdkmanager] del paquete [Android SDK Command-line Tools], respondiendo [y] a cada pregunta hasta que aparezca el mensaje “All SDK package licenses accepted.” (en [Windows], en [PowerShell]):

    1
    & "$env:LOCALAPPDATA\Android\Sdk\cmdline-tools\latest\bin\sdkmanager.bat" --licenses

    1. JDK: [Capacitor] 8 requiere JDK 21 o posterior. No es necesario instalar uno: [Android Studio] incluye el suyo, [JBR] (“JetBrains Runtime”), ubicado en su subcarpeta [jbr]. En las versiones recientes de [Android Studio], es un [Java] 25: esto requiere un pequeño ajuste en el proyecto [Android] generado por [Capacitor] (actualizar a [Gradle] 9.1), como se muestra en el ejemplo 01.

    2. Variables de entorno. [Capacitor] ([npx cap run android]) inicia por sí mismo la compilación con [Gradle] y la herramienta [adb]; necesita saber dónde están el SDK y el JDK. En [Windows], en Configuración / Sistema / Información del sistema / Configuración avanzada del sistema / Variables de entorno, cree dos variables de usuario:

    3. [ANDROID_HOME]: la carpeta del SDK de [Android]; de forma predeterminada, [C:\Users\<name>\AppData\Local\Android\Sdk] ([SDK Manager] la muestra en la parte superior de su ventana, [Android SDK Location]);

    4. [JAVA_HOME]: la carpeta del JDK de [Android Studio]; de forma predeterminada, [C:\Program Files\Android\Android Studio\jbr].

    Agregue también la carpeta [%ANDROID_HOME%\platform-tools] a la variable [Path] para poder escribir [adb] en una consola. Si [Android Studio] no está instalado en la ubicación predeterminada, el comando [npx cap open android] también requiere la variable [CAPACITOR_ANDROID_STUDIO_PATH]: la ruta del programa [studio64.exe]. Las nuevas variables solo son visibles para las consolas abiertas después de crearlas; debe reiniciar [VS Code]. Verifique en una consola nueva:

    1
2
    adb version
& "$env:JAVA_HOME\bin\java" -version

    2.4. Configuración de un emulador de Android

    Si no tiene un teléfono, puede probar la aplicación en un emulador [Android]: un teléfono virtual que se ejecuta en una ventana de su computadora. [Android Studio] instala el programa [Android Emulator] (si estaba marcado en [SDK Manager], vea más arriba), pero no proporciona un dispositivo virtual listo para usar: usted debe crear uno.

    • [Prerequisites]: la virtualización debe estar habilitada en el [BIOS] de la computadora y, en [Windows], debe estar marcada la característica [Windows Hypervisor Platform] ([Control Panel / Programs / Turn Windows features on or off]), lo que requiere reiniciar. De lo contrario, el emulador no se iniciará o será muy lento;
    • Abra [Device Manager] desde [Android Studio]: [More Actions / Virtual Device Manager] desde la pantalla de inicio, o [Tools / Device Manager] cuando hay un proyecto abierto (según la versión: [View / Tool Windows / Device Manager]);
    • haga clic en [Create Device], seleccione una plantilla (por ejemplo, [Pixel 8]) y luego [Next]. Seleccione una imagen de sistema reciente, [Android], para el procesador [x86_64], y descárguela con el vínculo [Download] ubicado junto a ella; luego [Next] y [Finish];
    • inicie el emulador con el botón [Play] de [Device Manager];
    • espere a que aparezca la pantalla de bienvenida de [Android] en la ventana del emulador: el primer inicio puede tardar varios minutos.

    A continuación, verifique que la computadora reconozca el emulador. Hay dos comandos para hacerlo:

    1
2
    adb devices
npx cap run android --list
    • Línea 1: [adb] enumera los dispositivos conectados a la computadora, uno por línea: su identificador (por ejemplo, [emulator-5554] para el primer emulador) seguido de su estado, que debería ser [device];
    • Línea 2: en la carpeta de un proyecto [Capacitor] ([examples_ionic], por ejemplo), [Capacitor] enumera los dispositivos en los que puede instalar la aplicación: los dispositivos conectados y en ejecución, así como los emuladores creados en [Android Studio], incluso si están apagados (sabe cómo iniciarlos). Es el equivalente de [flutter devices].

    [Note]: si [adb devices] muestra el emulador con el estado [offline], el emulador no ha terminado de arrancar, o [adb] está en un estado inconsistente. Pruebe lo siguiente en orden: (1) espere a que aparezca la pantalla de bienvenida y vuelva a ejecutar el comando; (2) reinicie [adb] con los tres comandos siguientes (en [Windows], dentro de [PowerShell]); el último debería mostrar [device] y no [offline]; (3) en [Device Manager], seleccione [Cold Boot Now] en el menú [⋮] del dispositivo, o incluso [Wipe Data] como último recurso.

    1
2
3
    & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" kill-server
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" start-server
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices

    Si el problema persiste, use [where.exe adb] para verificar que no haya otro [adb], de una versión diferente, en el [Path]: dos versiones de [adb] que compiten por la conexión causan este problema.

    Una vez reconocido el emulador, la aplicación se instala en él y se inicia con el siguiente comando, ubicado en la carpeta del proyecto, después de [npx ng build] y de [npx cap sync android] (vea el ejemplo 01); [--target] identifica el dispositivo por su ID; de lo contrario, el comando le solicita que seleccione uno:

    1
    npx cap run android --target emulator-5554

    En el emulador, la computadora que lo ejecuta tiene la dirección [10.0.2.2]: es allí donde la aplicación buscará el servidor JSON (vea el ejemplo 22).

    2.5. Preparación del teléfono Android

    Para ejecutar la aplicación en un teléfono real con [Android], el teléfono debe configurarse para poder controlarse desde la computadora:

    • habilite las opciones de desarrollador: abra [Settings / About phone], y luego toque [Build number] varias veces (normalmente 7) hasta que el teléfono indique que usted es desarrollador. Los nombres exactos varían según el fabricante;
    • habilite la [USB debugging] en las [Developer options] (menú agregado en el paso anterior);
    • conecte el teléfono a la computadora con un cable USB que transfiera datos (no solo que cargue el teléfono) y acepte en el teléfono la solicitud de autorización de depuración USB. En [Windows], si el teléfono no se reconoce, instale el controlador USB del fabricante (“OEM USB drivers”, vea developer.android.com/studio/run/oem-usb);
    • compruebe que la computadora detecte el teléfono: debe aparecer, con el estado [device], en la lista que muestra [adb devices] (el estado [unauthorized] significa que la solicitud de autorización no se aceptó en el teléfono) y en la lista que muestra [npx cap run android --list].

    El teléfono accederá al servidor [NestJS] a través de la dirección IP de la computadora en la red local (y no mediante [localhost], que, desde el punto de vista del teléfono, es el propio teléfono): esta configuración se describe en el ejemplo 22 y en el capítulo “Despliegue”.
