    12. Despliegue

    Durante el desarrollo, la aplicación se ejecuta bajo el control de [ng serve]: se compila sobre la marcha, con las verificaciones y los mensajes de [Angular] para el desarrollador, y se recarga con cada cambio. Para desplegarla, la compilamos: [ng build] produce una aplicación web optimizada, sin ninguna herramienta de desarrollo. Esta es la que desplegamos en un servidor web, y es TAMBIÉN la que [Capacitor] incluye en la aplicación [Android]: solo hay una compilación, para ambas plataformas.

    Sin ninguna opción, [ng build] usa la configuración [production] de [angular.json]: el código se optimiza (los nombres se acortan, se eliminan los espacios y los comentarios, y se elimina el código no utilizado) y se quitan las verificaciones destinadas al desarrollo. El compilador compiló la aplicación ([TypeScript], plantillas, [Angular], [Ionic]) a [JavaScript], en la carpeta [dist/rdvmedecins_ionic/browser/]:

    • [index.html]: LA página de la aplicación, que carga los archivos [JavaScript] y la hoja de estilos. A diferencia del cliente [Flutter], la aplicación genera contenido HTML estándar, que el propio navegador muestra;
    • los «chunks» iniciales, cargados al inicio: [Angular], [Ionic], el enrutador, los servicios y el diseño. 1,1 MB, o aproximadamente 220 KB una vez comprimidos por el servidor: esta es la estimación de la última columna;
    • segmentos «diferidos» (lazy): uno por pantalla ([login], [my-account]...), gracias a [loadComponent] en las rutas (véase [app.routes.ts]), y algunos otros para los componentes de [Ionic] cargados bajo demanda. Cada uno se descarga solo en la primera visita a la pantalla;
    • el nombre de cada archivo contiene un hash de su contenido ([main-FA64HVK2.js]): el servidor puede indicar al navegador que los almacene en caché indefinidamente, ya que una nueva versión tendrá nombres nuevos;
    • [i18n/] y [favicon.ico]: el contenido de la carpeta [public/], copiado tal cual;
    • [angular.json] establece «límites» para la configuración [production]: una advertencia si los chunks iniciales superan los 2 MB y un error si superan los 5 MB. La aplicación está muy lejos de alcanzar estos límites.

    La opción [--define "SERVER='...'"] no es necesaria aquí: servida por el servidor JSON, la aplicación usa la ruta relativa de [config.ts] ([/api/...]).

    1. Despliéguelo en el servidor. El servidor JSON puede servir un cliente web compilado (el archivo [src/web/client-spa.ts] del servidor): sus archivos se buscan en la carpeta [client/], en la raíz del servidor, o en la carpeta especificada por la variable de entorno [CLIENT_DIR] (archivo del servidor [src/config/paths.ts]; se puede escribir en el archivo [.env]). Dos opciones:

    2. copiar el CONTENIDO de la carpeta [dist/rdvmedecins_ionic/browser/] en una carpeta [client/] en la raíz del servidor JSON ([rdvmedecins-nestjs-json/client/index.html], [rdvmedecins-nestjs-json/client/main-FA64HVK2.js]...);

    3. o especificar directamente la carpeta generada por [ng build]:
    1
    CLIENT_DIR=../rdvmedecins_ionic/dist/rdvmedecins_ionic/browser

    (una ruta relativa a la raíz del servidor, o una ruta absoluta). Luego reinicie el servidor. Este muestra:

    1
2
    [Nest] LOG [RdvMedecins] web client served from .../rdvmedecins_ionic/dist/rdvmedecins_ionic/browser
[Nest] LOG [RdvMedecins] JSON server started: http://localhost:8080/api

    La aplicación completa ya está disponible en http://localhost:8080. El servidor sirve los archivos del cliente y devuelve [index.html] para cualquier otra dirección fuera de /api: recargar la página /schedule?doctorId=1&day=2026-10-13 funciona (es el navegador del cliente el que muestra la página de esta dirección). La página y la API provienen del mismo origen: no hay CORS, y la cookie del token se transmite.

    Para probar esto sin detener el servidor de desarrollo, se puede iniciar una instancia del servidor JSON en otro puerto, especificando ambas variables en la línea de comandos (aquí en [Linux] o [macOS]; en [Windows], con [PowerShell], primero se definen como [$env:PORT=8090] y [$env:CLIENT_DIR='...']):

    1
2
    cd rdvmedecins-nestjs-json
PORT=8090 CLIENT_DIR=../rdvmedecins_ionic/dist/rdvmedecins_ionic/browser npm run start:prod

    La aplicación es entonces accesible en http://localhost:8090; las dos instancias comparten la misma base de datos. Así se probó la versión web de este cliente: inicio de sesión, agenda, recarga de la página en una dirección como /schedule?... y el título traducido de la pestaña.

    El cliente también se puede desplegar en cualquier servidor web ([nginx], [Apache]...), siempre que reenvíe las solicitudes /api al servidor JSON (un «proxy inverso») y redirija a [index.html] las URL desconocidas: esto es lo que hace [ng serve] durante el desarrollo.

    12.2. La versión Android

    Compilar la aplicación [Android] requiere [Android Studio] y el SDK de [Android] (véase el capítulo «Configuración del entorno de desarrollo»). [Capacitor] 8 requiere JDK 21 o posterior: la versión incluida con [Android Studio] es adecuada.

    1. Cree el proyecto [Android] una sola vez:
    1
    npx cap add android

    El comando crea la carpeta [android/]: un proyecto completo de [Android Studio] (un proyecto [Gradle]), que contiene una actividad [Android] que muestra un [WebView], y los plugins de [Capacitor] que usa la aplicación ([@capacitor/app], [@capacitor/preferences]). Esta carpeta forma parte del proyecto: consérvela (y guárdela junto con el código fuente en [git]), porque aquí es donde se establecen el nombre, el ícono y la firma de la aplicación.

    Si el JDK es [Java] 25 (el que se usa en las versiones recientes de [Android Studio]), la versión de [Gradle] seleccionada por [Capacitor] (8.14) no logra que funcione ([Unsupported class file major version 69]): se cambia a [Gradle] 9.1 en el archivo [android/gradle/wrapper/gradle-wrapper.properties] (véase el ejemplo 01):

    1
    distributionUrl=https\://services.gradle.org/distributions/gradle-9.1.0-all.zip
    1. Compile la aplicación web y luego cópiela en el proyecto [Android]:
    1
2
    npx ng build
npx cap sync android
    • línea 1: la aplicación web, en [dist/rdvmedecins_ionic/browser/];
    • Línea 2: [cap sync] copia esta carpeta ([webDir] de [capacitor.config.ts]) en [android/app/src/main/assets/public/], junto con la configuración de [Capacitor] ([capacitor.config.json]), y actualiza los plugins. Con [server.cleartext] en [true], también agrega el atributo [android:usesCleartextTraffic="true"] al manifiesto del plugin, que se fusiona con el manifiesto de la aplicación durante la compilación: se permiten las solicitudes [http://] (sin cifrar) al servidor de desarrollo.

    Debe volver a ejecutar estos dos comandos después de cada cambio en el código de la aplicación.

    1. Ejecútela:
    1
    npx cap run android

    El comando enumera los dispositivos disponibles (emuladores creados en [Android Studio], teléfonos conectados por USB con la «depuración USB» habilitada), compila la aplicación, la instala en el dispositivo seleccionado y la inicia. También se puede abrir el proyecto en [Android Studio] ([npx cap open android]) y usar su botón «Run».

    En el emulador, la aplicación se conecta al servidor en la dirección [http://10.0.2.2:8080] (véase [config.ts]). En un teléfono real conectado a la misma red Wi-Fi que la computadora, es necesario proporcionarle la dirección de la computadora en esa red ([ipconfig] en [Windows]) con la siguiente sintaxis:

    1
2
3
    npx ng build --define "SERVER='http://192.168.1.20:8080'"
npx cap sync android
npx cap run android

    El firewall de la computadora debe permitir las conexiones entrantes en el puerto 8080.

    1. Pruébela. La aplicación es una página web mostrada por [WebView]: las herramientas de desarrollo de [Chrome], en la computadora, pueden inspeccionarla. Abra la dirección [chrome://inspect]: la aplicación del emulador o del teléfono aparece allí; «Inspect» abre la consola, el inspector de elementos y la pestaña «Network» (como las solicitudes a la API pasan por [CapacitorHttp], es decir, por código nativo, se ven menos allí que en la web: la consola de [Logcat], dentro de [Android Studio], las muestra).

    2. Un archivo de instalación de depuración (APK). En [Android Studio]: «Build > Generate App Bundles» o «APKs > Generate APKs». O bien, desde la línea de comandos, en la carpeta [android/]:

    1
2
    cd android
./gradlew assembleDebug

    (en [Windows]: [gradlew assembleDebug]). El archivo se genera en [android/app/build/outputs/apk/debug/app-debug.apk]. Está firmado con la clave de depuración de [Android Studio]: esto es suficiente para las pruebas. Instálelo en un teléfono conectado mediante [adb install app-debug.apk], o copiando el archivo al teléfono y abriéndolo ([Android] le pedirá entonces que permita la instalación de aplicaciones «de orígenes desconocidos»).

    1. Una versión de producción firmada. Una aplicación publicada debe firmarse con una clave propia del desarrollador, que debe mantenerse segura (todas las actualizaciones deben firmarse con la misma clave):

    2. en [Android Studio]: el menú «Build > Generate Signed App Bundle or APK...», que también permite crear la clave (un archivo «keystore», protegido por una contraseña);

    3. o mediante la línea de comandos: cree la clave con la herramienta [keytool] del JDK y luego compile la versión firmada:
    1
2
    keytool -genkey -v -keystore rdvmedecins.jks -keyalg RSA -keysize 2048 -validity 10000 -alias rdvmedecins
npx cap build android --keystorepath ../rdvmedecins.jks --keystorepass password --keystorealias rdvmedecins --keystorealiaspass password --androidreleasetype APK --signing-type apksigner
    • línea 1: crea la clave en el archivo [rdvmedecins.jks] (el comando solicita el nombre del desarrollador, la organización, etc.);
    • línea 2: [cap build] inicia la compilación de [Gradle] de la versión «release» ([assembleRelease]) y firma el archivo resultante con esta clave (la ruta de la clave es relativa a la carpeta [android/]). [--signing-type apksigner]: la firma la crea la herramienta [apksigner] del SDK, cuya carpeta, [build-tools/<version>], debe estar incluida en el PATH; sin esta opción, [Capacitor] usa [jarsigner], cuya firma ya no es aceptada por las versiones recientes de [Android] para un APK. [--androidreleasetype AAB] produciría un «Android App Bundle», el formato que espera [Google Play Store].

    También se puede describir la firma en el archivo [android/app/build.gradle] (un bloque [signingConfigs]; véase la documentación de [Android] titulada «Sign your app») y ejecutar directamente [./gradlew assembleRelease] (un APK, ubicado en [android/app/build/outputs/apk/release/]) o [./gradlew bundleRelease] (un App Bundle). La contraseña de la clave no debe escribirse en un archivo almacenado junto con el código fuente.

    1. Para una versión real:

    2. el nombre de la aplicación se establece en [capacitor.config.ts] ([appName]) y en [android/app/src/main/res/values/strings.xml]; su ícono se establece en los archivos [android/app/src/main/res/mipmap-*/] (la herramienta [@capacitor/assets] los genera todos a partir de una sola imagen);

    3. el servidor debe usar HTTPS (se transmiten contraseñas): se elimina [server.cleartext] de [capacitor.config.ts] y se compila la aplicación con la dirección pública del servidor ([--define "SERVER='https://rdvmedecins.example.com'"]).

    12.3. El servidor de producción

    En una producción real, no olvide el archivo [.env] en el servidor:

    • un [JWT_SECRET] largo y aleatorio;
    • un [CAPTCHA_TEST] vacío;
    • [COOKIE_SECURE=true] si el sitio se sirve mediante HTTPS (debe hacerse así): la cookie solo se transmite entonces a través de conexiones cifradas;
    • [TRUST_PROXY=true] si el servidor se encuentra detrás de un proxy ([nginx]...), para que el límite de intentos vea la dirección IP real de los clientes.

    El servidor no tiene reglas CORS que declarar: en la web, el propio servidor sirve al cliente (mismo origen); en [Android], las solicitudes se originan en el código nativo ([CapacitorHttp]), al que CORS no se aplica.

    A continuación se inicia el servidor compilado: [npm run build], seguido de [npm run start:prod].
