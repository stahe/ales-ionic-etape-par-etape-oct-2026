    9. Comunicación con el servidor

    El servidor JSON de [RdvMedecins] debe iniciarse ahora (puerto 8080), como se explicó en el capítulo anterior, preferiblemente en modo de prueba del CAPTCHA ([CAPTCHA_TEST=test]), que permite responder “test” a cualquier imagen.

    Los ejemplos 22 a 25 comparten algunos archivos, ubicados en la carpeta [src/app/common/] del proyecto: la dirección del servidor ([config.ts]), los tipos de respuesta ([types.ts]), las clases de error ([api-error.ts]), el servicio de solicitudes ([api.ts]) y una barra de inicio de sesión ([login-bar.ts]). Se presentan a lo largo de los ejemplos a medida que resultan pertinentes.

    9.1. Ejemplo 22: una primera solicitud HTTP

    9.1.1. ¿Dónde está el servidor?

    Para un cliente web servido por el propio servidor, la pregunta no se plantea: las solicitudes se envían al mismo origen que la página, mediante una dirección relativa ([/api/captcha]). Una aplicación instalada en un teléfono no tiene un origen utilizable: su página la sirve [Capacitor] mismo, desde https://localhost. Hay que proporcionar la dirección completa del servidor, y esta dirección depende de dónde se ejecute la aplicación:

    // =========================================================================
// src/app/common/config.ts - ¿DÓNDE está el servidor JSON?
// -------------------------------------------------------------------------
// La pregunta no se plantea para una aplicación web servida por el
// propio servidor: las solicitudes van al MISMO origen que la página
// (una dirección relativa, /api/...). Pero una aplicación MÓVIL no tiene un
// origen utilizable (en Android, la página es servida por Capacitor
// desde https://localhost): hay que darle la dirección completa del servidor.
//   - en desarrollo web (ng serve), el servidor de desarrollo de Angular
//     reenvía las solicitudes /api al servidor JSON (archivo
//     proxy.conf.json): basta una dirección relativa;
//   - el emulador de Android ve la computadora que lo ejecuta en
//     la dirección 10.0.2.2 (localhost, para él, es el propio emulador);
//   - un teléfono real, conectado a la misma red Wi-Fi que la computadora, debe
//     usar la dirección de la computadora en esta red (192.168.1.20...):
//     se proporciona al compilar la aplicación:
//         ng build --define "SERVER='http://192.168.1.20:8080'"
//     o bien se cambia la constante androidServer de más abajo.
// =========================================================================

import { Capacitor } from '@capacitor/core';

// la dirección del servidor para la aplicación Android, cuando no se impone nada más:
// la de la computadora, vista desde el emulador
const androidServer = 'http://10.0.2.2:8080';

// el valor dado por --define "SERVER='...'" en el momento de la compilación
// (ng build, ng serve). La opción reemplaza, en el código compilado, la palabra
// SERVER por el valor dado. Sin ella, SERVER no existe: typeof
// permite comprobarlo sin provocar un error
declare const SERVER: string | undefined;
const forcedServer = typeof SERVER === 'string' ? SERVER : '';

export const config = {
  // Capacitor.isNativePlatform(): true en la aplicación Android (o iOS),
  // false en un navegador; Capacitor.getPlatform(): 'android', 'ios' o 'web'
  serverUrl:
    forcedServer !== ''
      ? forcedServer
      : !Capacitor.isNativePlatform()
        ? '' // la web: mismo origen, direcciones relativas
        : Capacitor.getPlatform() === 'android'
          ? androidServer
          : 'http://localhost:8080',
};
    • línea 21: [Capacitor], el objeto de [@capacitor/core] que proporciona información sobre la plataforma en la que se ejecuta la aplicación. Se puede usar en cualquier lugar, incluso en un navegador;
    • línea 25: la dirección predeterminada es la de [Android]. El emulador es una máquina independiente con su propia red: para el emulador, [localhost] se refiere al propio emulador. La dirección especial [10.0.2.2] se refiere a la computadora que lo ejecuta;
    • líneas 31–32: una dirección impuesta durante la compilación de la aplicación mediante la opción [--define] de [Angular]: [ng build --define "SERVER='http://192.168.1.20:8080'"]. La compilación reemplaza el identificador [SERVER] en el código por el valor dado (una cadena, de ahí los apóstrofes). Sin esta opción, [SERVER] no existe: [declare const] informa al compilador de [TypeScript] que [SERVER] es un identificador cuya declaración no ve, y [typeof SERVER] permite comprobar su existencia sin causar un error. Es el equivalente exacto de [--dart-define] y [String.fromEnvironment] en [Flutter];
    • líneas 34–45: de lo contrario, una dirección específica de la plataforma. [Capacitor.isNativePlatform()] es verdadero en la aplicación [Android] (o [iOS]), pero falso en un navegador; [Capacitor.getPlatform()] devuelve 'android', 'ios' o 'web':
    • en el navegador (línea 41): una URL relativa (''), es decir, el mismo origen que la aplicación;
    • en [Android] (línea 43): la dirección de la línea 25;
    • en cualquier otro caso (línea 44, [iOS], que este curso no cubre): [localhost].

    Un teléfono real, conectado a la misma red Wi-Fi que la computadora del servidor, debe usar la dirección de la computadora en esa red (el comando [ipconfig] de [Windows] la proporciona): puede pasarla mediante [--define] durante la compilación, o modificar la constante de la línea 25. El firewall de la computadora también debe permitir las conexiones entrantes en el puerto 8080.

// capacitor.config.ts - la configuración de Capacitor
// -------------------------------------------------------------------------
// Capacitor convierte la aplicación web (la carpeta producida por ng build)
// en una aplicación Android: la envuelve en un proyecto de Android Studio
// (carpeta android/), donde se muestra en un "WebView", el motor del
// navegador Chrome del teléfono. Comandos (vea el ejemplo 01, "Running"):
//     npx cap add android       (solo una vez: crea la carpeta android/)
//     ng build                  (compila la aplicación web)
//     npx cap sync android      (la copia en el proyecto Android)
//     npx cap run android       (la ejecuta en un emulador o un teléfono)
// =========================================================================

import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  // el identificador único de la aplicación en el teléfono (y en Play Store)
  appId: 'fr.stahe.examples',
  // el nombre que se muestra bajo el ícono
  appName: 'Ionic Examples',
  // la carpeta de la aplicación web compilada (ng build)
  webDir: 'dist/examples_ionic/browser',
  server: {
    // permite solicitudes HTTP sin cifrar (http://10.0.2.2:8080) hacia
    // el servidor JSON de desarrollo (ejemplos 22 a 25)
    cleartext: true,
  },
  plugins: {
    // CapacitorHttp: las solicitudes HTTP de la aplicación ya no las realiza
    // el WebView sino el código nativo de Android. Consecuencias (vea los
    // ejemplos 22 y 23): no hay verificación de CORS (el servidor JSON no tiene nada
    // que permitir), y las cookies (la del token de autenticación) las
    // almacena Android y se reenvían automáticamente
    CapacitorHttp: {
      enabled: true,
    },
  },
};

export default config;
    • Líneas 23–27: [server.cleartext: true]. A partir de la versión 9 de [Android], una aplicación solo tiene permitido comunicarse mediante HTTPS. Nuestro servidor de desarrollo usa HTTP: lo permitimos. El comando [npx cap sync android] traslada este ajuste al proyecto [Android] (el atributo [android:usesCleartextTraffic="true"], agregado al manifiesto que [Capacitor] fusiona con el manifiesto de la aplicación). En producción, el servidor estaría en HTTPS y este ajuste desaparecería;
    • líneas 28–37: el plugin [CapacitorHttp]. Las solicitudes HTTP de la aplicación (las del cliente HTTP de [Angular], al igual que las de [fetch]) ya no las envía el WebView sino el código nativo de [Android]. Para un navegador, la aplicación (https://localhost) y el servidor (http://10.0.2.2:8080) parecerían tener dos orígenes distintos: el navegador exigiría que el servidor proporcione una autorización CORS, que el servidor no concede, y se negaría a incluir la cookie del token. El código nativo no tiene estas reglas. El código [TypeScript] de la aplicación, sin embargo, no cambia: es [Capacitor] quien redirige las solicitudes.

Nuevamente, hay dos orígenes, y [CapacitorHttp] no funciona dentro de un navegador. La solución es un proxy, configurado en [angular.json] (opción ["proxyConfig": "proxy.conf.json"] del destino [serve]):

    // =========================================================================
// src/app/ex22-http/ex22.page.ts - una primera solicitud HTTP al servidor
// -------------------------------------------------------------------------
// El servidor JSON de RdvMedecins debe estar en ejecución (puerto 8080). Se le pide
// un captcha: GET /api/captcha -> { "id": "...", "svg": "<svg ...>" }.
//
//   - HttpClient: el cliente HTTP de Angular (proporcionado a toda la aplicación
//     por provideHttpClient(), en main.ts). http.get<T>(address) devuelve
//     un Observable: la solicitud se envía cuando nos SUSCRIBIMOS a él (subscribe), y
//     la respuesta llega más tarde, con su cuerpo JSON ya decodificado;
//   - una respuesta de error (4xx, 5xx) o la ausencia de respuesta llegan
//     a la función error de la suscripción;
//   - la dirección del servidor depende de dónde se ejecute la aplicación
//     (navegador, emulador de Android, teléfono): véase common/config.ts;
//   - tres estados que mostrar: cargando, con éxito, con error;
//   - la imagen del captcha es SVG: una etiqueta <img> puede mostrarla.
// =========================================================================

import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { Component, DestroyRef, inject, signal } from '@angular/core';
import {
  IonBackButton, IonButton, IonButtons, IonCard, IonCardContent, IonContent, IonHeader, IonNote, IonProgressBar,
  IonTitle, IonToolbar,
} from '@ionic/angular';
import { Subscription } from 'rxjs';
import { config } from '../common/config';
import { Captcha, captchaImage } from '../common/types';

@Component({
  selector: 'app-ex22',
  imports: [
    IonHeader, IonToolbar, IonButtons, IonBackButton, IonTitle, IonContent, IonProgressBar, IonCard, IonCardContent,
    IonButton, IonNote,
  ],
  templateUrl: './ex22.page.html',
  styles: `
    .error { --background: #ffebee; --color: #333; margin: 12px 0; }
    .image { border: 1px solid #ddd; border-radius: 6px; padding: 4px; text-align: center; }
    .image img { height: 60px; }
    .id { font-family: monospace; font-size: 11px; margin: 8px 0; }
  `,
})
export class Ex22Page {
  private readonly http = inject(HttpClient);
  readonly server = config.serverUrl || '(same origin: /api, ng serve proxy)';
  readonly captchaImage = captchaImage;

  // el estado de la pantalla: señales
  readonly captcha = signal<Captcha | null>(null);
  readonly loading = signal(true);
  readonly error = signal<string | null>(null);
  readonly requestCount = signal(0);

  // la suscripción a la solicitud en curso (si hay una)
  private request?: Subscription;

  constructor() {
    this.load(); // la primera solicitud, apenas se crea la página
    // la página destruida (botón Atrás): la solicitud en curso se abandona
    inject(DestroyRef).onDestroy(() => this.request?.unsubscribe());
  }

  load(): void {
    // darse de baja de una solicitud aún en curso la CANCELA: su respuesta,
    // ahora inútil, nunca se procesará (ninguna respuesta "obsoleta")
    this.request?.unsubscribe();
    this.loading.set(true);
    this.error.set(null);
    // <Captcha>: el tipo del cuerpo JSON esperado (una promesa hecha al
    // compilador: nada se comprueba en tiempo de ejecución)
    this.request = this.http.get<Captcha>(`${config.serverUrl}/api/captcha`).subscribe({
      // next: la respuesta ha llegado (código 2xx), su cuerpo JSON está decodificado
      next: (captcha) => {
        this.captcha.set(captcha);
        this.requestCount.update((n) => n + 1);
        this.loading.set(false);
      },
      // error: una respuesta de error (4xx, 5xx), o ninguna respuesta
      // (servidor detenido, dirección incorrecta: status vale entonces 0)
      error: (e: HttpErrorResponse) => {
        this.error.set(e.status === 0 ? 'no response (status 0)' : `the server responded ${e.status}`);
        this.captcha.set(null);
        this.loading.set(false);
      },
    });
  }
}

    9.2. Ejemplo 23: inicio de sesión, cookie y sesión

    9.2.1. ¿Y la cookie?

    El servidor guarda el token JWT en una cookie. El cliente [Flutter] tenía, en este punto, que reemplazar su cliente HTTP por uno que lee el encabezado [Set-Cookie] de cada respuesta, organiza las cookies (y las almacena en el dispositivo), y las devuelve en el encabezado [Cookie] de cada solicitud: una aplicación [Flutter] no dispone de un navegador que lo haga por ella.

    Una aplicación [Ionic], en cambio, no tiene nada que escribir:

    • en el navegador de la computadora, es el navegador quien almacena la cookie y la devuelve, como lo hace con cualquier otro sitio web. El proxy de [ng serve] asigna el mismo origen a la aplicación y a la API: la cookie [SameSite=Strict] se acepta y se devuelve. El código de la aplicación no puede leer ni escribir esta cookie ([HttpOnly]);
    • en [Android], el complemento [CapacitorHttp] (ejemplo 22) hace pasar las solicitudes por el código nativo. [Capacitor] configura, al iniciar la aplicación, el administrador de cookies de [Android] (el del WebView) como administrador de las solicitudes nativas: las cookies recibidas se almacenan allí y se devuelven en las solicitudes siguientes al mismo servidor. Se conservan en el dispositivo (la nuestra tiene una duración definida por [Max-Age=7200]; solo se eliminan al iniciar la aplicación las cookies de “sesión”, que no tienen hora de expiración): la sesión permanece abierta al cerrar y volver a abrir la aplicación.

    Por lo tanto, el código de la aplicación nunca manipula el token, ni este se almacena en texto plano en el dispositivo (el cliente [Flutter] lo guardaba en [shared_preferences]).

// src/app/ex23-login/command.ts - una ACCIÓN, su estado, su resultado
// -------------------------------------------------------------------------
// Una acción asíncrona (iniciar sesión, guardar...) tiene un estado que
// la pantalla debe mostrar: ¿está EN CURSO (botón deshabilitado)? ¿terminó
// con un ERROR (mensaje)? Es el patrón "Command" de las guías de
// arquitectura (la de Flutter, por ejemplo), reducido a lo esencial:
//
//     readonly loginCommand = new Command();
//     this.loginCommand.execute(() => this.logIn());   // inicia la acción
//     loginCommand.running(), loginCommand.error()      // su estado
//
// Su estado está formado por SEÑALES: la plantilla que las lee se actualiza
// cuando el comando se inicia y cuando termina.
// =========================================================================

import { signal } from '@angular/core';

export class Command {
  private readonly _running = signal(false);
  private readonly _error = signal<unknown>(null);
  readonly running = this._running.asReadonly();
  readonly error = this._error.asReadonly();

  // ejecuta la acción, si no hay otra en curso
  async execute(action: () => Promise<void>): Promise<void> {
    if (this._running()) return; // sin doble envío (doble toque en el botón)
    this._running.set(true);
    this._error.set(null);
    try {
      await action();
    } catch (e) {
      this._error.set(e); // el error se CONSERVA, para mostrarlo
    } finally {
      // finally: se ejecuta en TODOS los casos, éxito o error
      this._running.set(false);
    }
  }

  clearError(): void {
    this._error.set(null);
  }
}

    Una acción asíncrona (iniciar sesión, guardar, etc.) tiene un estado que la pantalla debe mostrar: ¿está en curso (botón deshabilitado)? ¿Terminó con un error (mensaje)? Este es el modelo “Command” de las guías de arquitectura (el de [Flutter] lo llama así), reducido a lo esencial. El curso de [React] usaba para ello las “acciones” de [React] 19 ([useActionState]).

    • Líneas 19–23: una clase simple (cada pantalla crea la suya con [new]), cuyo estado consta de dos signals privados, expuestos como de solo lectura. La plantilla que lee [running()] o [error()] se actualiza cuando el comando comienza y cuando termina: es el papel que [ChangeNotifier] y [ListenableBuilder] desempeñaban en [Flutter];
    • líneas 26–38: ejecutar una acción: si otra acción está en curso, no hace nada (línea 27: evita el doble envío si se presiona el botón dos veces); de lo contrario, el comando pasa a “en curso”; en caso de excepción, se registra el error para mostrarlo (línea 33); en todos los casos ([finally], líneas 34–37), el comando deja de estar en curso. El error es de tipo [unknown]: en [JavaScript], se puede lanzar cualquier valor, y [TypeScript] por lo tanto no sabe qué es lo que [catch] captura.

  name: string;
  role: string;

  private readonly http = inject(HttpClient);
  readonly captchaImage = captchaImage;

  readonly user = signal<User | null>(null); // null: nadie ha iniciado sesión
  readonly doctors = signal<Doctor[]>([]);
  readonly captcha = signal<Captcha | null>(null);
  readonly ready = signal(false); // ¿ha terminado la comprobación inicial?
  readonly serverError = signal<string | null>(null);
  readonly loginCommand = new Command();
  // los campos del formulario, enlazados por [(ngModel)]
  readonly login = signal('admin');
  readonly password = signal('');
  readonly captchaAnswer = signal('');

  constructor() {
    this.checkSession();
  }

  private url(path: string): string {
    return `${config.serverUrl}/api${path}`;
  }

  // una solicitud GET cuyo cuerpo JSON queremos. Una respuesta que no sea 2xx
  // (o la ausencia de respuesta) rechaza la Promise con un HttpErrorResponse
  private read<T>(path: string): Promise<T> {
    return firstValueFrom(this.http.get<T>(this.url(path)));
  }

  // un POST: el objeto del cuerpo se envía como JSON (encabezado content-type: application/json)
  private post<T>(path: string, body: object): Promise<T> {
    return firstValueFrom(this.http.post<T>(this.url(path), body));
  }

  async loadCaptcha(): Promise<void> {
    this.captcha.set(await this.read<Captcha>('/captcha'));
    this.captchaAnswer.set('');
  }

  private async loadDoctors(): Promise<void> {
    this.doctors.set(await this.read<Doctor[]>('/doctors'));
  }

  // 1. ¿quién ha iniciado sesión? 200 -> el usuario; 401 -> nadie
  private async checkSession(): Promise<void> {
    try {
      this.user.set(await this.read<User>('/auth/me'));
      await this.loadDoctors();
    } catch (e) {
      // instanceof: una prueba de TIPO; e.status: el código de estado (0: sin respuesta)
      if (e instanceof HttpErrorResponse && e.status === 401) {
        await this.loadCaptcha();
      } else if (e instanceof HttpErrorResponse && e.status !== 0) {
        this.serverError.set(`The server responded ${e.status}.`);
      } else {
        this.serverError.set(`Is the RdvMedecins JSON server running (${config.serverUrl || 'port 8080'})?`);
      }
    }
    this.ready.set(true);
  }

  // el botón "Iniciar sesión": el Command ejecuta la acción y almacena su error
  submit(): void {
    this.loginCommand.execute(() => this.logIn());
  }

  // 2. el inicio de sesión
  private async logIn(): Promise<void> {
    try {
      const user = await this.post<User>('/auth/login', {
        login: this.login().trim(),
        password: this.password(),
        captchaId: this.captcha()?.id,
        captcha: this.captchaAnswer(),
      });
      this.password.set('');
      this.user.set(user);
      await this.loadDoctors();
    } catch (e) {
      if (!(e instanceof HttpErrorResponse)) throw e;
      // e.error: el cuerpo JSON de la respuesta de error, { statusCode, key, ... }
      const key: string = e.error?.key ?? 'ERRORS.SERVER_UNREACHABLE';
      await this.loadCaptcha(); // cada imagen se usa una sola vez
      // el error que el Command conservará
      throw new Error(`${e.status} - ${messages[key] ?? key}`);
    }
  }

  // el mensaje del error conservado por el comando
  errorMessage(): string {
    const error = this.loginCommand.error();
    return error instanceof Error ? error.message : String(error);
  }

  // 4. el cierre de sesión
  async logOut(): Promise<void> {
    await this.post('/auth/logout', {});
    this.user.set(null);
    this.doctors.set([]);
    await this.loadCaptcha();
  }
}

  firstName: string;
  lastName: string;

// src/app/common/api-error.ts - UNA clase para todos los errores de la API
// -------------------------------------------------------------------------
// Todas las respuestas de error del servidor de RdvMedecins tienen la misma forma:
//   { "statusCode": 409, "key": "ERRORS.LOGIN_TAKEN", "params": {...}, "fields": {...} }
// Pero una solicitud también puede fallar de OTRO modo: ninguna respuesta
// (red caída, servidor detenido, dirección incorrecta), o una respuesta que no
// proviene de nuestro servidor (una página de error de un proxy). El cliente HTTP
// de Angular informa de todos estos fallos con un HttpErrorResponse; lo
// convertimos en UNA sola clase, ApiError, que lleva la clave de traducción
// enviada por el servidor (y, si los hay, sus parámetros y el error de
// cada campo).
// =========================================================================

import { HttpErrorResponse } from '@angular/common/http';

// un objeto { name: texto }
export type Texts = Record<string, string>;

// "extends Error": un error de JavaScript de pleno derecho, que lanzamos
// (throw) y capturamos (catch); message vale "409 ERRORS.LOGIN_TAKEN"
export class ApiError extends Error {
  constructor(
    readonly statusCode: number, // 0: el servidor no respondió
    readonly key: string, // p. ej.: 'ERRORS.LOGIN_TAKEN'
    readonly params: Texts = {},
    readonly fields: Texts = {},
  ) {
    super(`${statusCode} ${key}`);
    this.name = 'ApiError';
  }

  // una respuesta de error del cliente HTTP de Angular -> un ApiError
  static fromResponse(response: HttpErrorResponse): ApiError {
    // status 0: sin respuesta (red caída, servidor detenido, dirección incorrecta)
    if (response.status === 0) {
      return new ApiError(0, 'ERRORS.SERVER_UNREACHABLE');
    }
    // error: el cuerpo de la respuesta, ya decodificado si es JSON
    const body: unknown = response.error;
    if (isObject(body) && typeof body['key'] === 'string') {
      return new ApiError(response.status, body['key'], texts(body['params']), texts(body['fields']));
    }
    // sin key: el proxy o la red respondieron en su lugar
    return new ApiError(
      response.status,
      response.status >= 500 ? 'ERRORS.SERVER_UNREACHABLE' : 'ERRORS.SERVER_ERROR',
    );
  }
}

// un "type guard": si la función devuelve true, TypeScript sabe que
// value es un objeto cuyas propiedades se pueden leer
function isObject(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

// un objeto JSON { "name": "ERRORS..." } -> Texts (vacío en caso contrario)
function texts(json: unknown): Texts {
  if (!isObject(json)) return {};
  return Object.fromEntries(Object.entries(json).map(([key, value]) => [key, String(value)]));
}

    Todas las respuestas de error del servidor tienen el mismo formato. Sin embargo, una solicitud también puede fallar de OTRA manera: ninguna respuesta, o una respuesta que no proviene de nuestro servidor. El cliente HTTP de [Angular] notifica todos estos fallos como una [HttpErrorResponse]; los convertimos en UNA sola clase, [ApiError].

    • Línea 18: [Record<string, string>]: un objeto cuyas propiedades son cadenas;
    • líneas 22–31: [extends Error]: un error de pleno derecho de [JavaScript], que se lanza ([throw]) y se captura ([catch]), junto con su pila de llamadas. Los parámetros del constructor precedidos por [readonly] declaran e inicializan los campos (una abreviatura de [TypeScript]): un estado (0: ninguna respuesta), una clave de traducción, sus parámetros y el error de cada campo. El mensaje del error (línea 29) es “401 LOGIN.ERROR”, para una visualización rápida;
    • líneas 34–49: una [HttpErrorResponse] → una [ApiError]. Estado 0: ninguna respuesta (líneas 36–38). De lo contrario, [response.error] es el cuerpo de la respuesta, ya decodificado si es JSON (línea 40); si tiene una clave de tipo cadena [key], respondió nuestro servidor (líneas 41–42). De lo contrario, un intermediario (proxy, red) respondió en su lugar (líneas 45–48);
    • líneas 54–56: un type guard ([value is Record<string, unknown>]): una función cuyo resultado, [true], informa al compilador del tipo de su parámetro. Después de [isObject(body)], sabe que [body] es un objeto cuyas propiedades se pueden leer. Esto es lo que hacía en un solo paso la instrucción “if-case” de [Dart];

// src/app/common/api.ts - solicitudes a la API, en una línea
// -------------------------------------------------------------------------
// En el ejemplo 23, cada solicitud repetía los mismos pasos: dirección del
// servidor, prefijo /api, conversión del Observable en Promise, lectura
// del cuerpo del error... Los agrupamos aquí, en un SERVICIO:
//
//   const doctors = await this.api.get<Person[]>('/doctors');
//   await this.api.post('/appointments', { day, slotId: 3 });
//
//   - si tiene éxito, la Promise devuelve el cuerpo JSON, DECODIFICADO;
//   - si falla, se rechaza con un ApiError.
// Todas las solicitudes pasan por el método request: es el lugar donde
// trataríamos un problema COMÚN a todas ellas (véase el caso de estudio y la
// respuesta 401). Usado por los ejemplos 24 y 25.

import { HttpClient, HttpErrorResponse } from '@angular/common/http';
import { inject, Injectable } from '@angular/core';
import { firstValueFrom } from 'rxjs';
import { config } from './config';
import { ApiError } from './api-error';

export type Method = 'GET' | 'POST' | 'PUT' | 'DELETE';

// providedIn: 'root': una sola instancia, para toda la aplicación
@Injectable({ providedIn: 'root' })
export class Api {
  private readonly http = inject(HttpClient);

  // <T>: el tipo de la respuesta esperada, elegido por quien llama
  async request<T>(method: Method, url: string, body?: unknown): Promise<T> {
    try {
      // http.request devuelve un Observable; firstValueFrom lo convierte en
      // Promise (la solicitud se envía en ese momento). Un objeto de cuerpo se envía
      // como JSON (encabezado content-type: application/json, que el servidor exige
      // en un POST); la respuesta JSON se decodifica (null si su cuerpo está vacío)
      return await firstValueFrom(this.http.request<T>(method, `${config.serverUrl}/api${url}`, { body }));
    } catch (e) {
      // el cliente HTTP informa de CUALQUIER fallo (4xx, 5xx, sin respuesta) con un
      // HttpErrorResponse: lo convertimos. El resto (una anomalía) pasa tal cual
      throw e instanceof HttpErrorResponse ? ApiError.fromResponse(e) : e;
    }
  }

  get<T>(url: string): Promise<T> {
    return this.request<T>('GET', url);
  }

  // un POST siempre tiene un cuerpo JSON: {} por defecto
  post<T>(url: string, body: unknown = {}): Promise<T> {
    return this.request<T>('POST', url, body);
  }

  put<T>(url: string, body: unknown): Promise<T> {
    return this.request<T>('PUT', url, body);
  }

  delete<T>(url: string, body?: unknown): Promise<T> {
    return this.request<T>('DELETE', url, body);
  }
}

export function formatDay(d: Date): string {
  const twoDigits = (n: number) => String(n).padStart(2, '0');
  return `${d.getFullYear()}-${twoDigits(d.getMonth() + 1)}-${twoDigits(d.getDate())}`;
}

// mañana: el día de hoy, más uno
function tomorrow(): Date {
  const d = new Date();
  d.setDate(d.getDate() + 1);
  return d;
}

@Injectable()
export class ScheduleModel {
  private readonly rdvmedecins = inject(RdvMedecins);

  // ==== el estado ====
  readonly user = signal<User | null>(null);
  readonly doctors = signal<Person[]>([]);
  readonly clients = signal<Person[]>([]);
  readonly doctorId = signal<number | null>(null);
  readonly day = signal(formatDay(tomorrow()));
  readonly clientId = signal<number | null>(null);
  readonly schedule = signal<Schedule | null>(null);
  readonly loading = signal(false);
  readonly message = signal<Message | null>(null);

  private readonly cache = new Map<string, Schedule>();
  private readNumber = 0;

  // ==== los valores calculados ====
  readonly loggedIn = computed(() => this.user() !== null);
  readonly isManager = computed(() => this.loggedIn() && this.user()?.role !== 'USER');

  // ==== las acciones ====
  async changeUser(u: User | null): Promise<void> {
    this.user.set(u);
    this.doctors.set([]);
    this.clients.set([]);
    this.schedule.set(null);
    this.doctorId.set(null);
    this.message.set(null);
    this.cache.clear(); // los derechos han cambiado: se olvida todo
    if (u === null) return;
    this.doctors.set(await this.rdvmedecins.getDoctors());
    // un USUARIO recibiría 403
    if (this.isManager()) this.clients.set(await this.rdvmedecins.getClients());
  }

  chooseDoctor(id: number): void {
    this.doctorId.set(id);
    this.message.set(null);
    this.readSchedule();
  }

  chooseDay(day: string): void {
    this.day.set(day);
    this.message.set(null);
    this.readSchedule();
  }

  chooseClient(id: number | null): void {
    this.clientId.set(id);
  }

  book(c: ScheduleSlot): Promise<void> {
    return this.act(
      () => this.rdvmedecins.book(this.day(), c.id, this.isManager() ? this.clientId() : null),
      `Slot ${timeRange(c)} booked.`,
    );
  }

  cancel(c: ScheduleSlot): Promise<void> {
    return this.act(() => this.rdvmedecins.cancelAppointment(c.appointmentId!), `Appointment of ${timeRange(c)} cancelled.`);
  }

  // una acción, y luego SIEMPRE una nueva lectura de la agenda: el SERVIDOR es la referencia
  private async act(action: () => Promise<void>, success: string): Promise<void> {
    try {
      await action();
      this.message.set({ success: true, text: success });
    } catch (e) {
      this.message.set({ success: false, text: e instanceof ApiError ? e.message : String(e) });
    }
    await this.readSchedule();
  }

  private async readSchedule(): Promise<void> {
    const id = this.doctorId();
    if (id === null) return;
    const key = `${id}/${this.day()}`;
    const number = ++this.readNumber;
    // primero el caché (o nada), luego la lectura
    this.schedule.set(this.cache.get(key) ?? null);
    this.loading.set(true);
    try {
      const read = await this.rdvmedecins.getSchedule(id, this.day());
      if (number !== this.readNumber) return; // se ha iniciado una lectura más reciente
      this.cache.set(key, read);
      this.schedule.set(read);
    } catch (e) {
      if (number !== this.readNumber) return;
      this.schedule.set(null);
      this.message.set({ success: false, text: e instanceof ApiError ? e.message : String(e) });
    }
    this.loading.set(false);
  }
}

export class Ex25Page {
  private readonly api = inject(Api);
  private readonly confirm = injectConfirmation();
  readonly tr = inject(Translations);
  readonly languages = languages;
  readonly titles = ['Mr', 'Mme', 'Melle', 'Dr']; // "Dr": el servidor lo rechazará
  readonly fullName = fullName;

  readonly user = signal<User | null>(null);
  readonly clients = signal<Person[]>([]);

  // el formulario: SIN reglas de validación, todo lo verifica el servidor
  readonly form = inject(NonNullableFormBuilder).group({
    title: ['Mr'],
    firstName: [''],
    lastName: [''],
    login: [''],
    password: [''],
  });
  // null: creación; en caso contrario, el id del cliente modificado y la versión leída con su registro
  readonly editedId = signal<number | null>(null);
  private version = 0;

  // el mensaje general del último error, y el de un éxito
  readonly pageError = signal<ApiError | null>(null);
  readonly success = signal<Success | null>(null);
  // el envío al servidor: un Command (ejemplo 23), que indica si está en curso
  readonly sending = new Command();

  constructor() {
    addIcons({ languageOutline, createOutline, trashOutline });
    this.tr.start();
  }

  isAdmin(): boolean {
    return this.user()?.role === 'ADMIN';
  }

  private async reload(): Promise<void> {
    this.clients.set(await this.api.get<Person[]>('/clients'));
  }

  async onUserChange(u: User | null): Promise<void> {
    this.user.set(u);
    this.clients.set([]);
    if (u?.role === 'ADMIN') await this.reload();
  }

  // el error de un campo, devuelto por el servidor, traducido ('': sin error)
  fieldError(field: Field): string {
    const key = this.form.controls[field].errors?.['server'];
    return typeof key === 'string' ? this.tr.t(key) : '';
  }

  private clearMessages(): void {
    this.pageError.set(null);
    this.success.set(null);
  }

  newForm(): void {
    this.editedId.set(null);
    this.version = 0;
    // reset: los valores iniciales, y ya ningún error
    this.form.reset();
    this.clearMessages();
  }

  edit(c: Person): void {
    this.editedId.set(c.id);
    // la VERSIÓN leída con el registro se reenvía con la modificación: si alguien
    // ha modificado el registro mientras tanto, el servidor responderá 409 CONCURRENT_UPDATE
    this.version = c.version;
    this.form.reset({ title: c.title, firstName: c.firstName, lastName: c.lastName, login: c.login ?? '', password: '' });
    this.clearMessages();
  }

  // el botón "Guardar"
  submit(): void {
    this.sending.execute(() => this.save());
  }

  private async save(): Promise<void> {
    this.clearMessages();
    const input = { ...this.form.getRawValue(), version: this.version };
    const id = this.editedId();
    try {
      const client =
        id === null
          ? await this.api.post<Person>('/clients', input)
          : await this.api.put<Person>(`/clients/${id}`, input);
      this.newForm(); // formulario vaciado, mensajes borrados...
      // ... excepto este
      this.success.set({
        key: id === null ? 'FORM.ADDED' : 'FORM.UPDATED',
        params: { name: `${client.firstName} ${client.lastName}`, login: client.login ?? '' },
      });
      await this.reload();
    } catch (e) {
      if (!(e instanceof ApiError)) throw e;
      this.pageError.set(e); // el mensaje general
      // el error de cada campo: se entrega a su control, que
      // pasa a ser inválido (ng-invalid); markAsTouched lo marca como "tocado"
      // (ng-touched): Ionic muestra entonces su errorText
      for (const [field, key] of Object.entries(e.fields)) {
        const control = this.form.get(field);
        control?.setErrors({ server: key });
        control?.markAsTouched();
      }
    }
  }

  async remove(c: Person): Promise<void> {
    const name = `${c.firstName} ${c.lastName}`;
    if (!(await this.confirm(this.tr.t('FORM.DELETE_CONFIRM', { name })))) return;
    this.clearMessages();
    try {
      await this.api.delete(`/clients/${c.id}`);
      this.success.set({ key: 'FORM.DELETED', params: { name } });
    } catch (e) {
      if (e instanceof ApiError) this.pageError.set(e);
    }
    await this.reload();
  }
}
